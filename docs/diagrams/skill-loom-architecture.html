How Skill Loom keeps repo chains local and publishes optional copies

Long image

A

Answer

The repository is the source of truth for repo-first chains. The active agent runs them locally; a trusted SSH-backed Podman bridge optionally reaches the hosted catalog and shared library. The HTTP editor remains loopback-only.

  1. Chain files stay in chains/<id>.json; publication state stays in a versioned sidecar.
  2. Selected skills are copied into the client repository and are not overwritten.
  3. Remote CLI access uses SSH-backed Podman, not HTTP ingress.

Applies toCurrent repo-first workflow and approved single-host pilot

1

Which components own the repo-first path?

The client owns its chain and skill files. The hosted service supplies reviewed catalog entries and stores an optional published copy.

How does a hosted selection become a local run?

Review exact package identities before copying. After the chain and packages are local, execution uses the active agent session and does not need the host.

  1. Choose host project

    Select the trusted host connection.

  2. Review exact entries

    Confirm the package identities before copying.

  3. Copy selected packages

    Keep existing repository files unchanged.

  4. Create and validate chain

    Save ordered steps in the repository.

  5. Run in active session

    Publish an optional shared copy afterward.

What else remains in the codebase?

Managed runs and portable bundles remain compatibility workflows. They are separate from repo-chain execution and do not change its active-session contract.
