# How Skill Loom keeps repo chains local and publishes optional copies {#architecture}

The repository is the source of truth for repo-first chains. The active agent runs them locally; a trusted SSH-backed Podman bridge optionally reaches the hosted catalog and shared library. The HTTP editor remains loopback-only.

- Chain files stay in `chains/<id>.json`; publication state stays in a versioned sidecar.
- Selected skills are copied into the client repository and are not overwritten.
- Remote CLI access uses SSH-backed Podman, not HTTP ingress.

## Which components own the repo-first path? {#system span=12}

The client owns its chain and skill files. The hosted service supplies reviewed catalog entries and stores an optional published copy.

@architecture id=system-map title="Repo-first chain access paths"
| agent | Agent session | external | source:workflow |
| repo | Repo files | database | source:repo-cli |
| bridge | SSH/Podman bridge | backend | source:bridge |
| host | Hosted Loom | backend | source:pilot |
| agent > repo | local run |
| agent > bridge | remote ops |
| bridge > host | Podman |

## How does a hosted selection become a local run? {#journey}

Review exact package identities before copying. After the chain and packages are local, execution uses the active agent session and does not need the host.

@steps id=hosted-steps
| project | Choose host project | Select the trusted host connection. |
| review | Review exact entries | Confirm the package identities before copying. |
| copy | Copy selected packages | Keep existing repository files unchanged. |
| author | Create and validate chain | Save ordered steps in the repository. |
| run | Run in active session | Publish an optional shared copy afterward. |

## Which data stays local or hosted? {#ownership}

| Data | Owner | Boundary |
| --- | --- | --- |
| `chains/<id>.json` | Client repository | Canonical ordered chain |
| `chains/<id>.publish.json` | Client repository | Last successful hosted id and revision |
| `.agents/skills/` | Client repository | Selected, no-overwrite package copies |
| Catalog | Host operator | Mounted read-only to Loom |
| Shared chain library | Hosted service | Optional copies updated by expected revision |
| HTTP editor | Local machine | The server rejects non-loopback hosts |

## What did the live pilot prove? {#pilot}

One authorized client completed catalog review/copy, local chain execution, first publish/update, and a stale-revision conflict [P6 evidence](source:pilot-evidence).

@facts id=pilot-scope
| Host | Ubuntu 26.04 ARM64; rootless Podman 5.7.0 |
| Backup and reboot | Disposable config-volume restore and Podman-socket reboot check passed |
| App state | The app container remained stopped after reboot |
| Accepted exception | The pre-pilot backup timing gate was missed |
| Remaining gates | Unauthorized identity, SELinux enforcing, alternate platforms, app boot startup, live image update/rollback, chain-referenced package copy, and local run after disconnect |

Consult `docs/current-gaps.md` and the implementation evidence register before extending this support claim.

## What else remains in the codebase? {#compatibility}

Managed runs and portable bundles remain compatibility workflows. They are separate from repo-chain execution and do not change its active-session contract.
