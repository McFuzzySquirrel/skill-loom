How do I author a repo chain from a hosted catalog?

Long image

A

Answer

Keep the chain in the repository and run it in the active agent session. Use the hosted catalog only to copy selected packages, and publish a shared-library copy only when the user confirms.

  1. Review exact catalog entry ids and fingerprints before copying.
  2. Copy only to the client repository's .agents/skills/; existing packages are never overwritten.
  3. Local execution needs no hosted connection after the chain and packages are present.
  4. Hosted updates use the sidecar revision; stale conflicts require comparison and explicit recovery.

Applies toRepo-first workflow; one approved Ubuntu host/client pilot

How do I go from catalog to a run?

Diagram structure
  • Select packages copy
  • Author chain author
  • Run locally run
  • author → run
  • copy → author

The host provides selected packages, but the client keeps its path and chain files. The agent can stop after local execution; publication is a separate choice and requires explicit confirmation.

  1. Select packages ↗

    Select the host project over the trusted SSH-backed Podman connection. Confirm each catalog id, fingerprint, and package inventory before copying into .agents/skills/. Do not send the client repository path to the host. Stop on conflicts or partial success.

  2. Author chain ↗

    Save the canonical chain as chains/<id>.json; keep hosted mapping in its sidecar.

  3. Run locally ↗

    Preview ordered steps and inputs, then ask for confirmation. No hosted connection is needed once local.

After local execution, publish a shared copy only with explicit confirmation; updates require the sidecar revision check.

Which pilot claims are verified?
