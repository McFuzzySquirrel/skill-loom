# Skill Loom 0.1.0 (Draft Release Notes)

**Release date:** Unreleased. `package.json` declares version `0.1.0`; no Git tag or npm publication exists. Published or tagged release notes should replace this status and verify the date.

## Summary

Skill Loom is a single-user local web application for assembling, saving, and running ordered chains of installed agent skills. It inventories the skills a selected harness can load, builds a reusable recipe, preflights the run, and executes the chain in a real terminal against OpenCode or GitHub Copilot CLI.

Skills are **model-invoked** context. Skill Loom guarantees the prompt text and order it sends, not that the harness loads or fires a named skill. The chain order is prompt order, **not a guarantee** of skill execution.

## Highlights

- Project workspace with recent projects, a folder browser, optional `git init`, and a per-project chain library.
- OpenCode filesystem catalog and Copilot CLI catalog, with extra skill directories, warnings, and bounded copy-into-project. New project copies and bundle imports use `.agents/skills/` for either harness; OpenCode also discovers legacy `.opencode/skills/` packages.
- Explicit remote HTTPS/SSH skill-repository registration and refresh into pinned, bounded local snapshots; discovered packages can be reviewed and copied into a project.
- Remote native-agent catalog entries can be installed without overwriting and selected by pinned identity on compatible harness surfaces; preflight verifies the installed definition. Bundle version 2 preserves a selected agent definition; the standalone current-conversation runner inspects but does not execute selected-agent bundles.
- Chain builder with step reordering, named inputs, `{{name}}` placeholders, shared/fresh/fork session modes, and a per-chain automatic-permission opt-in.
- Portable chain bundles with bounded package validation, project-local source preference, explicit conflict choices, and actionable missing or ambiguous source errors.
- Global chain library with independent snapshots and import-with-new-id.
- Deterministic preflight with hard blocks, warnings, and explicit acknowledgements; preflight makes no model call.
- Supervised runs with explicit done/failed/skipped outcomes and automatic runs that advance only on an adapter-declared harness signal.
- Frozen run snapshots, one global active run, bounded 200-line/32 KiB step tails, and explicit interrupted-run recovery.
- Test chains in fresh managed project workspaces, keep them out of the recent-project list, retain outputs for review, and require explicit cleanup after active runs end. These directories are not OS security sandboxes.
- Terminal-dominant run view with xterm.js screen-reader mode, Escape-to-leave focus, and a companion run details page.
- Separate project skills, chains, and details workspaces with system, light, and dark appearance options.
- Local `skill-loom` CLI packaged from a local tarball, with a shared profile owner, reviewed-approval commands for import, run start and actions, workspace tests, and a skill-only path documented in the [standalone skill guide](../standalone-skill-guide.md).
- Checkout-only, explicitly approved [managed OpenCode acceptance probe](../OPERATIONS.md#managed-opencode-acceptance) for ordered two-step artifacts, shared sessions, pause, abort, orderly recovery and verified tracked-resource/session cleanup. Deterministic fixtures are not a live acceptance claim.

## Compatibility and Prerequisites

- **Node.js 24 or newer** (`package.json` declares `>=24`).
- **npm** and a native toolchain for `node-pty`: Python 3, `make`, and a C++ compiler.
- **Stable OpenCode CLI 2.2.5 or newer** for OpenCode chains, installed and authenticated. This minimum is not proof of automatic advancement compatibility.
- **GitHub Copilot CLI 1.0.105** for Copilot chains, installed and authenticated.
- A desktop browser. The layout and terminal target desktop use.
- Git is optional; a non-Git project skips the dirty-tree check.
- Copilot discovery follows `copilot skill list --json`; an OpenCode-only legacy package under `.opencode/skills/` is not thereby available to Copilot.
- The server is loopback-only. There is no authentication, TLS, or supported remote deployment.

## Installation or Upgrade

From a checkout:

```bash
npm install
npm run build
npm start
```

Then open `http://127.0.0.1:7373`.

From a local tarball:

```bash
npm run build
npm pack
npx --yes --package=./skill-loom-cli-0.1.0.tgz skill-loom
```

This is not a registry release. The package is `"private": true`; no upgrade channel, migration tool, or rollback package exists beyond rebuilding or restoring a previous checkout.

## Known Limitations

- **Automatic OpenCode advancement is not proven end-to-end.** Historical evidence recorded `OSC7501_PRODUCT_PARSER_MISMATCH` (colon-separated parameters) and `OSC7501_CLEAR_BEFORE_IDLE` (child clear incorrectly resetting root working). Both parser issues are fixed; the supplied OpenCode 2.2.6 rerun passes product advancement, recall and cleanup. A managed multi-step automatic journey is still unverified, and automatic CLI starts remain blocked.
- **Legacy package locations are not migrated.** OpenCode continues to discover `.opencode/skills/`, but new copies and imports use `.agents/skills/`; Copilot availability depends on its CLI catalog. Existing packages remain untouched.
- **At the time of this validation, `/api/health` reported an inactive `activeRun` placeholder.** The later standalone CLI branch reports the existing owner's state or its persisted pointer instead; neither proves process liveness.
- **One harness per chain.** Per-step harness switching and per-step model selection are not supported.
- **Fork is not always native.** OpenCode headless supports `--fork`; supervised OpenCode and all Copilot forks use a deterministic handoff note labelled **not a native session fork**.
- **One active run globally.** A second start is rejected while a run is starting, running, paused, or awaiting user input.
- **Run history is bounded.** Only the newest 200 lines or 32 KiB per step are persisted; there is no full transcript.
- **No authentication or TLS.** Loopback-only is the security boundary, not a temporary default.
- **No published npm package or Git release tag.** `0.1.0` is a local declared version.
- **Live evidence is platform-specific.** Historical probes cover Linux ARM64 with OpenCode 2.2.5 and Copilot CLI 1.0.105. The supplied passing execution probe covers Linux x64 with OpenCode 2.2.6 and Copilot CLI 1.0.107; Copilot retains its exact-version warning. This is not a cross-platform acceptance claim.

## Security and Privacy

- Skill Loom is **loopback-only**: it binds to `127.0.0.1`, rejects non-loopback hosts, and has **no authentication** because it is not designed for remote access. Never expose it through a proxy, tunnel, container publish, or remote host.
- The server owns filesystem traversal, path canonicalization, persistence, process spawning, and PTY handling. The browser performs no shell execution.
- Harness processes use an executable plus argument array with `shell: false`; prompts and paths are never composed into a shell string.
- Credentials and tokens are never read into Skill Loom's config, logs, or API responses. Authentication checks report presence evidence only.
- Copilot's `~/.copilot/config.json` is read-only to Skill Loom. Broad automatic flags require a per-chain opt-in and are shown at preflight and on the run.
- No telemetry, crash reporting, or remote logging is sent by Skill Loom. Git access occurs only after explicit source refresh; user-invoked harness CLIs and package installation may also use the network.
