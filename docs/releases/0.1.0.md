# Skill Loom 0.1.0 (Draft Release Notes)

**Release date:** Unreleased. `package.json` declares version `0.1.0`; no Git tag or npm publication exists. Published or tagged release notes should replace this status and verify the date.

## Summary

Skill Loom is a single-user local tool for assembling, saving, and running ordered chains of agent skills. It is driven by the `skill-loom` CLI and companion Agent Skills; its only web screen is a visual chain editor opened with `skill-loom edit`. Chains can be shared as reviewed portable `.loom.json` bundles or run inside the current harness session with the `loom-run-bundle` skill.

Skills are **model-invoked** context. Skill Loom guarantees the prompt text and order it sends, not that the harness loads or fires a named skill. The chain order is prompt order, **not a guarantee** of skill execution.

## Highlights

- Companion skills (`scenario-discovery`, `loom-chain-workflow`, `loom-run-bundle`) cover discovery, reviewed packaging, optional workspace testing, import, and execution in the current host session. The first two offer to install the CLI when it is missing.
- Shared-owner CLI (`service`, `project`, `chain`, `catalog`, `discovery`, `bundle`, `run`, `workspace`) with versioned JSON envelopes, stdin payloads, reviewed digests and explicit confirmations.
- Project-independent drafts plus project chains, with version 3 chain documents, revision preconditions, and atomic writes.
- A single visual chain editor for reordering steps, editing instructions, managing `{{inputs}}`, and saving back to the draft or project chain.
- Skill catalogs for OpenCode filesystem discovery and Copilot `copilot skill list --json`, including explicit remote HTTPS/SSH registration, pinned snapshots, bounded paging, and no execution of package content.
- Portable chain bundles with complete referenced skill packages, project-local precedence, bounded validation, explicit conflict handling, and no-overwrite import. Version 2 preserves one selected native agent.
- Deterministic preflight with hard blocks, warnings, and explicit acknowledgements; preflight makes no model call.
- Supervised and automatic managed runs with frozen snapshots, one global active run, bounded step tails, explicit interruption recovery, `run events`, and `run attach`.
- Managed disposable test workspaces and discovery workspaces with retained output and explicit cleanup. These are working directories, not OS security sandboxes.
- Profile ownership lock and authenticated local control transport: a private socket on Unix and mutually authenticated loopback TLS on Windows.
- A skill-only path documented in the [standalone skill guide](../standalone-skill-guide.md).

Removed in this line: the multi-screen web application (projects, catalogs, discovery, libraries, test-workspace and run screens), the WebSocket terminal transport, the global chain-template library, and the shared bundle library. Their storage and safety decisions are recorded in [ADR-0027](../adr/0027-cli-and-skill-driven-workflow.md) and [ADR-0028](../adr/0028-single-purpose-chain-editor.md).

## Compatibility and Prerequisites

- **Node.js 24 or newer** (`package.json` declares `>=24`).
- **npm** and a native toolchain for `node-pty`: Python 3, `make`, and a C++ compiler.
- **Stable OpenCode CLI 2.2.5 or newer** for OpenCode chains, installed and authenticated. The minimum does not establish automatic advancement compatibility.
- **GitHub Copilot CLI 1.0.105** for Copilot chains, installed and authenticated.
- A desktop browser only for the chain editor. Run output is streamed to `skill-loom run attach`, not to the browser.
- Windows profile security prefers PowerShell 7 and accepts Windows PowerShell 5.1 with .NET 4.7.2+ as an availability fallback. Native PowerShell 7 verification is still pending. See [host selection and verification status](../admin-guide.md#identity-secrets-and-tls).
- Git is optional; a non-Git project skips the dirty-tree preflight check.
- The server is loopback-only. There is no authentication, TLS, or supported remote deployment.

## Installation or Upgrade

From a checkout:

```bash
npm install
npm run build
npm start
```

`npm start` serves the API and the built chain editor on the loopback origin. To use the `skill-loom` command globally, pack the tarball and use the global install below.

From a local tarball:

```bash
npm run build
npm pack
npx --yes --package=./skill-loom-cli-0.1.0.tgz skill-loom
```

Global install from the same tarball:

```bash
npm install -g ./skill-loom-cli-0.1.0.tgz \
  --allow-scripts="file:$PWD/skill-loom-cli-0.1.0.tgz,node-pty"
skill-loom --version
```

The `--allow-scripts` value is needed on npm 11.20 and newer to silence the advisory for a local tarball install; npm identifies a `file:` dependency by path, so a name-only list does not cover the package itself. See [Install globally](../../README.md#install-globally).

There is no registry release, upgrade channel, migration tool, or rollback package beyond rebuilding or restoring a previous checkout. Stop the service before replacing a checkout and back up `~/.config/loom` and project `.loom/chains/` directories first.

## Known Limitations

- **Automatic OpenCode advancement is not proven end-to-end.** The record-aware parser passed a user-supplied OpenCode 2.2.6 probe, including product advancement, recall, and cleanup. A managed multi-step automatic journey is still unverified, so automatic CLI starts remain blocked.
- **Protected managed skill execution and descendant containment remain open gates.** See [known gaps](../current-gaps.md).
- **Legacy package locations are not migrated.** OpenCode continues to discover `.opencode/skills/`, but new copies and imports use `.agents/skills/`; Copilot availability depends on its CLI catalog.
- **One harness per chain.** Per-step harness switching and per-step model selection are not supported.
- **Fork is not always native.** OpenCode headless supports `--fork`; supervised OpenCode and all Copilot forks use a deterministic handoff note explicitly labelled **not a native session fork**.
- **One active run globally.** A second start is rejected while a run is starting, running, paused, or awaiting user input.
- **Run history is bounded.** Only the newest 200 lines or 32 KiB per step are persisted; there is no full transcript.
- **No authentication, TLS, or remote access.** Loopback-only is the security boundary.
- **No published npm package or Git release tag.** `0.1.0` is a local declared version.
- **Live evidence is platform-specific.** See the validation section below.

## Security and Privacy

- Skill Loom is **loopback-only**: it binds to `127.0.0.1`, rejects non-loopback hosts, and has **no authentication** because it is not designed for remote access. Never expose it through a proxy, tunnel, container publish, or remote host.
- The server owns filesystem traversal, path canonicalization, persistence, process spawning, and PTY handling. The chain editor performs no shell execution.
- Harness processes use an executable plus argument array with `shell: false`; prompts and paths are never composed into a shell string.
- Credentials and tokens are never read into Skill Loom's config, logs, or API responses. Authentication checks report presence evidence only.
- Copilot's `~/.copilot/config.json` is read-only to Skill Loom. Broad automatic flags require a per-chain opt-in and are shown at preflight and on the run.
- No telemetry, crash reporting, or remote logging is sent by Skill Loom. Git access occurs only after explicit source refresh; user-invoked harness CLIs and package installation may also use the network.
